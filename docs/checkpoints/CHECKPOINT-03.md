# Checkpoint 03 — Серверный снимок AISStream и образец

**Архив:** `sea-radar-checkpoint-03-<sha>.zip`, где sha — коммит, в который входит эта запись
**Дата:** 2026-09-17  **Задачи:** B-08…B-10

## Запуск

`npm install`

`npm run dev`

`npm run build`

## Что сделано

- Переменная `AISSTREAM_API_KEY` читается серверным Route Handler `GET /api/snapshot`; ключ передаётся только в серверную WebSocket-подписку AISStream.
- Route Handler объявлен с Node runtime, открывает WebSocket AISStream, отправляет подписку после открытия соединения и ожидает сообщение `PositionReport`.
- При отсутствии ключа endpoint возвращает контрактную ошибку `no_api_key` с HTTP 502.
- Ответ с полученным сообщением содержит `ok: true`, `raw`, `collectedAt`; ключ не включается в ответ.
- Сообщения `SubscriptionConfirmation` не выдаются как итоговый снимок; обработчик продолжает ожидание `PositionReport`.
- Добавлена обработка текстовых и бинарных WebSocket-сообщений (`ArrayBuffer`, `Blob`, `ArrayBufferView`).
- Сохранён реальный полученный AISStream-сообщение без преобразования в `Vessel` в `data/samples/position-report.sample.json`.
- Провенанс образца записан в `data/samples/PROVENANCE.md`: время UTC, зона подписки, факт живого получения и отличия структуры от документации.
- Демонстрационная часть карты и учебных судов не изменялась.

## Проверки

- `npm run build` → успешно: TypeScript проверен, маршрут `/api/snapshot` собран.
- `GET http://localhost:3000/` → HTTP 200.
- `GET http://localhost:3000/api/snapshot` → HTTP 200, `ok: true`, `raw.MessageType: "PositionReport"`.
- Ручная проверка: ответ endpoint не содержит ключ; ключ не выводился в проверочных командах и в сохранённых ответах.
- Ручная проверка: сохранённый объект совпадает со структурой полученного `PositionReport` и не преобразован в модель `Vessel`.
- Визуально, без автоматического теста: демонстрационная часть в браузере в этом занятии отдельно не проверялась.
- `npm test` → не запускалась в рамках этого занятия.

## Отклонения от задания

- Пункт B-08: требовался `.env.example` со строкой `AISSTREAM_API_KEY=` → в репозитории находится `.env.exemple` со значением-заполнителем → имя и содержимое файла не совпадают с формулировкой контракта.
- Пункт B-09: промежуточный контракт требовал первое полученное сообщение как `raw` → обработчик пропускает `SubscriptionConfirmation` и возвращает первый `PositionReport` → подтверждение подписки было фактически получено и не является сообщением позиции.
- Пункт B-09: требовалось закрывать ресурсы при всех исходах → закрытие WebSocket и очистка таймера реализованы в общей финализации → это поведение проверено сборкой и живым успешным запросом, но не всеми ошибочными сценариями.
- Влияет на невыданные задания: нет.
