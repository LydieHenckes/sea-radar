# Checkpoint 04 — Преобразование и снимок настоящих позиций

**Архив:** `sea-radar-checkpoint-04-<sha>.zip`, где sha — коммит, в который входит эта запись
**Дата:** 2026-09-24  **Задачи:** B-11…B-13

## Запуск

`npm install`

`npm run dev`

`npm run build`

## Что сделано

- `positionReportToVessel` преобразует одно сообщение `PositionReport` в существующую структуру `Vessel`; невалидная позиция не создаёт судно, а невалидные скорость и курс становятся `null`.
- `GET /api/snapshot` собирает позиции в течение заданного окна, дедуплицирует по идентификатору и возвращает метаданные снимка либо контрактную ошибку HTTP 502.
- В `MapScreen` добавлена кнопка «Загрузить настоящие позиции» и состояния демонстрации, загрузки, успеха, пустого результата и ошибки.
- При загрузке демонстрационный таймер останавливается; наборы попыток заменяют друг друга. Используются существующие карта, значки судов и `VesselCard`.

## Проверки

- `npx tsc --noEmit` → успешно.
- `npm run build` → успешно; маршрут `/api/snapshot` собран.
- `npm test` → passed 3 / failed 0 (три теста выбора судна).
- Ручная проверка: временный `scripts/check-parser.ts` прочитал образец и вывел семь преобразованных полей и соответствующие исходные значения.
- Ручная проверка: локальный `GET /api/snapshot` вернул HTTP 200, `count: 3`, `reason: "window_elapsed"`, `truncated: false`; один `Vessel` содержал поля `id`, `name`, `lat`, `lon`, `speedKnots`, `courseDeg`, `timestamp`, `source`.
- Визуально, без автоматического теста: после нажатия кнопки отобразилась подпись `AISStream · снимок за 15 с · получен 17:16:58 UTC · судов: 5 · выборка неполная`; на карте было 5 маркеров.
- Ручная проверка bundle: в `.next/static` строки `AISSTREAM_API_KEY`, `APIKey` и `your_value` не найдены.

## Живое подключение к AISStream

успешно: локальный запрос вернул 3 судна за окно, `reason: "window_elapsed"`; при ручном нажатии кнопки отображено 5 судов. Во время обеих проверок окно было 15 секунд; текущее значение конфигурации после проверки — 45 секунд.

## Что осталось за рамками

- Автоматические проверки collector-а с подставными источником и часами, включая гонки финализации, лимит 100, timeout без сообщения, disconnect, provider error и abort, не добавлены и не запускались.
- Сценарии пустого ответа, ошибки, лимита 100 и двух параллельных запросов не проверялись вручную.
- Проверка отсутствия ключа в каждом возможном runtime-сценарии логирования не проводилась; сканирование client assets и просмотр кода не выявили его вывода.
- Ошибочное тело ответа и отображение `attemptedAt` в интерфейсе отдельно не проверялись.

## Отклонения от задания

- B-12: требовалось окно 15 секунд → текущее `SNAPSHOT_WINDOW_MS` равно 45 000 мс → значение было изменено после live-проверки; эта конфигурация не соответствует контракту B-12.
- B-13: время ошибки должно браться из `attemptedAt` → интерфейс выводит сообщение ошибки, но не показывает время → поле времени не добавлено в отображение.
- Влияет на невыданные задания: да, B-13 зависит от длительности снимка; для соответствия контракту B-12 требуется 15 секунд.
