Напиши преобразователь: одно сообщение PositionReport → структура судна,
та самая, которая заведена на первой неделе. Новых полей не добавляй.

Пиши по файлу data/samples/position-report.sample.json — по фактическому
регистру и вложенности из него, а не по документации и не по памяти.

Источники полей:
  id          ← MetaData.MMSI, строкой
  name        ← MetaData.ShipName, пробелы по краям обрезаются,
                пустая строка → null
  lat, lon    ← Message.PositionReport.Latitude / Longitude
  speedKnots  ← Message.PositionReport.Sog
  courseDeg   ← Message.PositionReport.Cog
  timestamp   ← MetaData.time_utc, приведённое к ISO 8601 с миллисекундами
  source      ← 'aisstream'
  Валидация. Позиция принимается, только если:
  — lat число в [-90, 90], lon число в [-180, 180]; 91 и 181 — это значения
    «недоступно», они невалидны; значения вне диапазона (95, -200) и нечисловые,
    включая координату строкой, невалидны;
  — MMSI присутствует и непустой;
  — время парсится.
Невалидная позиция судно не создаёт. Судна с координатами 0,0 не появляется.

Скорость: 102.3 («недоступно»), любое значение вне [0, 102.2], отсутствующее
или нечисловое поле → null. Ноль остаётся нулём.
Курс: 360 («недоступно»), любое вне [0, 360), отсутствующее или нечисловое поле → null.
При невалидных скорости и курсе позиция всё равно принимается.
Отдельно обрати внимание на формат time_utc в образце — он не ISO, и new Date() его напрямую не разбирает. Посмотри, как он выглядит в файле, и напиши разбор под него.
